## Default texts

Splide lets you change every text it puts in the carousel. The docs strongly recommend translating these defaults for accessibility.

| Key | Default text | Placeholders | Where it appears (source) |
|---|---|---|---|
| `prev` | `Previous slide` | none | `aria-label` of the previous arrow |
| `next` | `Next slide` | none | `aria-label` of the next arrow |
| `first` | `Go to first slide` | none | `aria-label` of the **next** arrow when it will wrap to the first slide (`type: 'loop'` on the last slide, or `rewind: true` at the end) |
| `last` | `Go to last slide` | none | `aria-label` of the **previous** arrow when it will wrap to the last slide (`type: 'loop'` on the first slide, or `rewind: true` at the start) |
| `slideX` | `Go to slide %s` | `%s` = 1-based slide number | `aria-label` of each pagination button when `perPage` is 1 or a `focus`/`isNavigation` option is set. Also the `aria-label` of each navigation slide (`isNavigation: true`) |
| `pageX` | `Go to page %s` | `%s` = 1-based page number | `aria-label` of each pagination button when `perPage > 1` and neither `focus` nor `isNavigation` is set |
| `play` | `Start autoplay` | none | `aria-label` of the toggle button (`.splide__toggle`) while autoplay is stopped |
| `pause` | `Pause autoplay` | none | `aria-label` of the toggle button while autoplay is running |
| `carousel` | `carousel` | none | `aria-roledescription` of the root element |
| `select` | `Select a slide to show` | none | `aria-label` of the pagination `<ul>` (`role="tablist"`) |
| `slide` | `slide` | none | `aria-roledescription` of each slide. Removed from navigation slides when `slideFocus` is on |
| `slideLabel` | `%s of %s` | 1st `%s` = slide number, 2nd `%s` = total slides (`splide.length`, clones excluded) | `aria-label` of each slide, unless the slide has its own `aria-label` in HTML |

The `aria-roledescription` attribute gives a non-interactive element a human-readable description for assistive technology.

`label` and `labelledby` (the root's accessible name) are separate options, not part of `i18n`. Translate them too (see [accessibility.md](accessibility.md)).

## How placeholders are filled

From source (`utils/string/format`):

```js
// format( string, replacements ): each replacement fills the FIRST remaining '%s'
string = string.replace( '%s', String( replacement ) );
```

- Placeholders are positional and filled left to right. There is no `%1$s` or `%2$s` syntax, so a translation cannot reorder them. For `slideLabel`, the first `%s` is always the slide number and the second is always the total. Choose wording that keeps that order, for example `'%s / %s'`.
- Extra `%s` stay literal. If you leave one out (for example `slideLabel: 'Slide %s'`), the leftover value is dropped.
- Numbers are inserted as plain JS numbers (`1`, `2`, ...), not localized digits.
- Labels are computed when components mount. Slide labels are recomputed on `refresh()`, and after `add()` or `remove()`, which refresh too. Pagination labels are recomputed whenever the pagination is rebuilt (`updated`, `refresh`).

To show localized digits, such as Arabic-Indic numerals, there are two places to handle. Slides keep an `aria-label` written in HTML. Pagination buttons can be relabeled in `pagination:mounted`, which fires every time the pagination is rebuilt. Register the handler before `mount()`:

```js
var nf = new Intl.NumberFormat( 'ar-EG' );
// SPLIDE_I18N: see "Complete language sets" below
var splide = new Splide( '.splide', { i18n: SPLIDE_I18N.ar, direction: 'rtl' } );

splide.on( 'pagination:mounted', function ( data ) {
  data.items.forEach( function ( item ) {
    item.button.setAttribute( 'aria-label', 'الانتقال إلى الشريحة ' + nf.format( item.page + 1 ) );
  } );
} );

splide.mount();
```

(This uses the `slideX` wording. With `perPage > 1`, use the `pageX` wording.)

## Modifying texts for one carousel

Pass an object to the `i18n` option. Splide merges it into the defaults, so you only list the keys you change:

```js
new Splide( '#splide', {
  i18n: {
    prev: 'Previous slide',
    next: 'Next slide',
  }
} ).mount();
```

**(source)** The merge is deep and key by key: the defaults, then `Splide.defaults.i18n`, then the constructor's `i18n`, then `data-splide` JSON. Keys you omit keep the value from the previous layer.

**(source)** Set `i18n` before `mount()`. Components read it when they are created, so changing it later with `splide.options = { i18n: ... }` applies only partly. The pagination picks it up when rebuilt, the toggle label on its next update, and slide labels after `refresh()`. Arrow labels and the root's `aria-roledescription` keep the old texts. To switch language at runtime, `destroy()` the instance and create a new one.

## Setting texts for all carousels (`Splide.defaults`)

For several carousels, set the texts once with the `Splide.defaults` property:

```js
Splide.defaults = {
  i18n: {
    prev: 'Previous slide',
    next: 'Next slide',
  },
};
```

From source:

- `Splide.defaults` is read in the `Splide` constructor, so set it **before** any `new Splide()`.
- Assigning `Splide.defaults = { ... }` replaces the whole defaults object, discarding any other defaults set earlier, for example by another script. To change only the texts, assign the key:

```html
<script src="https://cdn.jsdelivr.net/npm/@splidejs/splide@4.1.4/dist/js/splide.min.js"></script>
<script>
  Splide.defaults.i18n = {
    prev: 'Diapositive précédente',
    next: 'Diapositive suivante',
  };
</script>
<!-- later scripts: new Splide( ... ).mount(); -->
```

- A partial `Splide.defaults.i18n` is fine because it is deep-merged with the built-in defaults. Per-instance `i18n` keys still override it.

## Setting texts from HTML (`data-splide`)

**(source)** The constructor parses the root's `data-splide` attribute as JSON and merges it **last**, so it overrides constructor options. Invalid JSON throws `Error: [splide] Invalid JSON`.

```html
<section class="splide" aria-label="Productos destacados"
  data-splide='{"i18n":{"prev":"Diapositiva anterior","next":"Diapositiva siguiente"}}'>
  ...
</section>
```

The JSON uses double quotes, so wrap the attribute in single quotes, or HTML-escape the JSON inside a double-quoted attribute (see the Shopify and PHP sections).

## Content-based wording

Content-based texts are better when possible. In a list of articles, "Move to next article" fits better than "Move to next slide":

```js
new Splide( '#articles', {
  i18n: {
    prev      : 'Previous article',
    next      : 'Next article',
    first     : 'Go to first article',
    last      : 'Go to last article',
    slideX    : 'Go to article %s',
    pageX     : 'Go to page %s',
    select    : 'Select an article to show',
    slide     : 'article',
    slideLabel: 'Article %s of %s',
  },
} ).mount();
```

## Arabic and other RTL carousels

**(source)** Splide does not read the `dir` attribute. Set `direction: 'rtl'` yourself, even on a page with `<html dir="rtl">`. Otherwise the slides move in the LTR direction. With `direction: 'rtl'`:

- The root gets `splide--rtl`, which the core CSS turns into `direction: rtl`. The arrow wrapper gets `splide__arrows--rtl`, and the themes swap the arrow sides and flip the SVGs.
- Pagination keys reverse (Left arrow = next dot), as do the optional `keyboard` shortcuts. Pagination follows `paginationDirection`, which defaults to `direction`.
- Drag and swipe directions reverse.

Full Arabic example:

```html
<!doctype html>
<html lang="ar" dir="rtl">
<head>
  <meta charset="utf-8">
  <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@splidejs/splide@4.1.4/dist/css/splide.min.css">
</head>
<body>
  <section id="featured" class="splide" aria-labelledby="featured-title">
    <h2 id="featured-title">منتجات مميزة</h2>
    <div class="splide__track">
      <ul class="splide__list">
        <li class="splide__slide"><img src="1.jpg" alt="قميص كتان"></li>
        <li class="splide__slide"><img src="2.jpg" alt="وشاح صوف"></li>
        <li class="splide__slide"><img src="3.jpg" alt="حقيبة قماش"></li>
      </ul>
    </div>
  </section>

  <script src="https://cdn.jsdelivr.net/npm/@splidejs/splide@4.1.4/dist/js/splide.min.js"></script>
  <script>
    new Splide( '#featured', {
      direction: 'rtl',
      perPage  : 2,
      i18n     : {
        prev      : 'الشريحة السابقة',
        next      : 'الشريحة التالية',
        first     : 'الانتقال إلى الشريحة الأولى',
        last      : 'الانتقال إلى الشريحة الأخيرة',
        slideX    : 'الانتقال إلى الشريحة %s',
        pageX     : 'الانتقال إلى الصفحة %s',
        play      : 'تشغيل العرض التلقائي',
        pause     : 'إيقاف العرض التلقائي مؤقتًا',
        carousel  : 'عرض دوّار',
        select    : 'اختر شريحة لعرضها',
        slide     : 'شريحة',
        slideLabel: '%s من %s',
      },
    } ).mount();
  </script>
</body>
</html>
```

To choose the direction automatically, read it before mounting (the `splide--rtl` class does not exist yet at that point):

```js
var el = document.querySelector( '#featured' );

new Splide( el, {
  direction: getComputedStyle( el ).direction === 'rtl' ? 'rtl' : 'ltr',
} ).mount();
```

## Shopify themes: passing translated strings from Liquid

Theme translations live in `locales/*.json` and are read in Liquid with the `t` filter. Keep `%s` literally in the strings: Liquid ignores it, and Splide fills it later. Liquid interpolation (`{{ name }}`) is a separate mechanism and is not used here.

Shopify HTML-escapes translated content by default, and keys ending in `_html` are not escaped. This decides how you can pass the strings:

| Method | Works with normal keys? | Why |
|---|---|---|
| One `data-*` attribute per key: `data-i18n-prev="{{ 'splide.prev' \| t }}"` | Yes (recommended) | The output is already entity-escaped, which is safe in an attribute, and the browser decodes the entities when JS reads the attribute. Do not add `\| escape`, which would double-escape |
| Inline JSON or a `<script>` with `\| t \| json` | Only with `_html` keys | Entities are not decoded inside `<script>`, so an escaped apostrophe would reach the `aria-label` as `&#39;` |
| `data-splide` built with `capture` | Only with `_html` keys | Same reason as inline JSON |

### 1. Locale files

`locales/en.default.json`:

```json
{
  "splide": {
    "prev": "Previous slide",
    "next": "Next slide",
    "first": "Go to first slide",
    "last": "Go to last slide",
    "slide_x": "Go to slide %s",
    "page_x": "Go to page %s",
    "play": "Start autoplay",
    "pause": "Pause autoplay",
    "carousel": "carousel",
    "select": "Select a slide to show",
    "slide": "slide",
    "slide_label": "%s of %s"
  }
}
```

`locales/fr.json` uses the same keys with the French strings from the set above.

### 2. Recommended: data attributes on one shared element, read once

Put this once in `layout/theme.liquid` (any place in `<body>`):

```liquid
<div id="SplideI18n" hidden
  data-prev="{{ 'splide.prev' | t }}"
  data-next="{{ 'splide.next' | t }}"
  data-first="{{ 'splide.first' | t }}"
  data-last="{{ 'splide.last' | t }}"
  data-slide-x="{{ 'splide.slide_x' | t }}"
  data-page-x="{{ 'splide.page_x' | t }}"
  data-play="{{ 'splide.play' | t }}"
  data-pause="{{ 'splide.pause' | t }}"
  data-carousel="{{ 'splide.carousel' | t }}"
  data-select="{{ 'splide.select' | t }}"
  data-slide="{{ 'splide.slide' | t }}"
  data-slide-label="{{ 'splide.slide_label' | t }}"></div>

<script src="https://cdn.jsdelivr.net/npm/@splidejs/splide@4.1.4/dist/js/splide.min.js" defer></script>
<script src="{{ 'sliders.js' | asset_url }}" defer></script>
```

`assets/sliders.js`:

```js
( function () {
  // Splide i18n key -> data attribute on #SplideI18n
  var MAP = {
    prev: 'data-prev', next: 'data-next', first: 'data-first', last: 'data-last',
    slideX: 'data-slide-x', pageX: 'data-page-x', play: 'data-play', pause: 'data-pause',
    carousel: 'data-carousel', select: 'data-select', slide: 'data-slide', slideLabel: 'data-slide-label',
  };

  function readI18n( el ) {
    var i18n = {};
    if ( ! el ) return i18n;
    Object.keys( MAP ).forEach( function ( key ) {
      var value = el.getAttribute( MAP[ key ] );
      if ( value ) i18n[ key ] = value; // missing keys keep Splide's English default
    } );
    return i18n;
  }

  Splide.defaults.i18n = readI18n( document.getElementById( 'SplideI18n' ) );

  var instances = new WeakMap();

  function init( scope ) {
    scope.querySelectorAll( '.splide' ).forEach( function ( el ) {
      if ( instances.has( el ) ) return;
      var rtl = getComputedStyle( el ).direction === 'rtl';
      instances.set( el, new Splide( el, { direction: rtl ? 'rtl' : 'ltr' } ).mount() );
    } );
  }

  function teardown( scope ) {
    scope.querySelectorAll( '.splide' ).forEach( function ( el ) {
      var splide = instances.get( el );
      if ( splide ) {
        splide.destroy();
        instances.delete( el );
      }
    } );
  }

  init( document ); // deferred scripts run after parsing, so the DOM is ready

  // Theme editor: sections are re-rendered without a page load.
  document.addEventListener( 'shopify:section:load', function ( e ) { init( e.target ); } );
  document.addEventListener( 'shopify:section:unload', function ( e ) { teardown( e.target ); } );
} )();
```

The same `readI18n` works per carousel if you put the `data-*` attributes on each `.splide` root instead and pass `{ i18n: readI18n( el ) }` to the constructor.

### 3. Alternative: inline JSON (use `_html` keys)

Name the locale keys with an `_html` suffix (`"prev_html": "Diapositive précédente"`) so the output is not entity-escaped, then let `json` produce valid JSON strings:

```liquid
<script type="application/json" id="SplideI18nJson">
  {
    "prev": {{ 'splide.prev_html' | t | json }},
    "next": {{ 'splide.next_html' | t | json }},
    "first": {{ 'splide.first_html' | t | json }},
    "last": {{ 'splide.last_html' | t | json }},
    "slideX": {{ 'splide.slide_x_html' | t | json }},
    "pageX": {{ 'splide.page_x_html' | t | json }},
    "play": {{ 'splide.play_html' | t | json }},
    "pause": {{ 'splide.pause_html' | t | json }},
    "carousel": {{ 'splide.carousel_html' | t | json }},
    "select": {{ 'splide.select_html' | t | json }},
    "slide": {{ 'splide.slide_html' | t | json }},
    "slideLabel": {{ 'splide.slide_label_html' | t | json }}
  }
</script>
```

```js
var node = document.getElementById( 'SplideI18nJson' );
if ( node ) {
  Splide.defaults.i18n = JSON.parse( node.textContent );
}
```

Keep `<` out of these strings, because `_html` content is output raw.

### 4. Alternative: `data-splide` on the section (no JS needed for the texts)

```liquid
{%- capture splide_config -%}
  {"perPage":3,"i18n":{"prev":{{ 'splide.prev_html' | t | json }},"next":{{ 'splide.next_html' | t | json }},"slideLabel":{{ 'splide.slide_label_html' | t | json }}}}
{%- endcapture -%}

<section class="splide"
  aria-label="{{ section.settings.heading | escape }}"
  data-splide="{{ splide_config | strip | escape }}">
  ...
</section>
```

`escape` turns the JSON's quotes into `&quot;` inside the double-quoted attribute, and the browser decodes them before Splide's `JSON.parse`. `data-splide` overrides constructor options, so `new Splide( el ).mount()` is all the JS you need.

## WordPress / PHP: passing translated strings

Strings from `__()` are not HTML-escaped, so encode the JSON first and then escape it for the attribute:

```php
<?php
$splide_config = array(
  'i18n' => array(
    'prev'       => __( 'Previous slide', 'my-theme' ),
    'next'       => __( 'Next slide', 'my-theme' ),
    'first'      => __( 'Go to first slide', 'my-theme' ),
    'last'       => __( 'Go to last slide', 'my-theme' ),
    /* translators: %s: slide number */
    'slideX'     => __( 'Go to slide %s', 'my-theme' ),
    /* translators: %s: page number */
    'pageX'      => __( 'Go to page %s', 'my-theme' ),
    'play'       => __( 'Start autoplay', 'my-theme' ),
    'pause'      => __( 'Pause autoplay', 'my-theme' ),
    'carousel'   => __( 'carousel', 'my-theme' ),
    'select'     => __( 'Select a slide to show', 'my-theme' ),
    'slide'      => __( 'slide', 'my-theme' ),
    /* translators: 1: slide number, 2: total slides. Keep this order. */
    'slideLabel' => __( '%s of %s', 'my-theme' ),
  ),
  'direction' => is_rtl() ? 'rtl' : 'ltr',
);
?>
<section class="splide" aria-label="<?php esc_attr_e( 'Featured posts', 'my-theme' ); ?>"
  data-splide="<?php echo esc_attr( wp_json_encode( $splide_config ) ); ?>">
  ...
</section>
```

Without WordPress, use `htmlspecialchars( json_encode( $config, JSON_UNESCAPED_UNICODE ), ENT_QUOTES, 'UTF-8' )` for the attribute value.

## What i18n does not cover

- The root's accessible name: the `label` / `labelledby` options or HTML `aria-label` / `aria-labelledby`.
- Any visible text you write, such as the toggle button's play/pause text or captions.
- Arrow buttons: their only text is the `aria-label`, and the SVG has none. Custom HTML arrows have their `aria-label` overwritten from `i18n`.
- Slides with their own HTML `aria-label` keep it instead of `slideLabel`. Navigation slides (`isNavigation`) always get `slideX`, even if they have an HTML `aria-label`.
- Digits are not localized (see [How placeholders are filled](#how-placeholders-are-filled)).

## Docs vs source

| Topic | Docs (i18n page) | Source |
|---|---|---|
| `first` | "`aria-label` of a previous arrow" | Used on the **next** arrow when it wraps to the first slide (`Arrows.ts`: `nextIndex > -1 && index > nextIndex ? i18n.first : i18n.next`). The accessibility guide agrees with the source |
| `last` | "`aria-label` of a next arrow" | Used on the **previous** arrow when it wraps to the last slide (`prevIndex > -1 && index < prevIndex ? i18n.last : i18n.prev`) |
| Key order | `select` listed before `slide` | Same keys and texts; only the order differs (`slide` comes before `select` in `I18N`) |
| `select` text | `Select a slide to show` | Same. The accessibility page prints "Select slide to show", which is a typo there |

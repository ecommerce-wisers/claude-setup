# i18n

Translating the texts Splide adds to a React Splide carousel: the `i18n` option, strings from props or an i18n library, switching languages, RTL and localized digits.

Source: https://splidejs.com/guides/i18n/ and https://splidejs.com/integration/react-splide/

React Splide 0.7.12 from npm (`@splidejs/react-splide`), which bundles Splide core 4.1.3 (identical to 4.1.4 here). Keys and defaults come from the core's `constants/i18n.ts`. Where each string is used was traced through `components/*`. Facts marked **(source)** are not on the docs page; facts marked *tested* were checked in headless Chrome with React 19, in production and in development with StrictMode.

## Default texts

Splide lets you change every text it puts in the carousel. The docs strongly recommend translating these defaults for accessibility.

| Key | Default text | Placeholders | Where it appears (source) |
|---|---|---|---|
| `prev` | `Previous slide` | none | `aria-label` of the previous arrow |
| `next` | `Next slide` | none | `aria-label` of the next arrow |
| `first` | `Go to first slide` | none | `aria-label` of the **next** arrow when it will wrap to the first slide (`type: 'loop'` on the last slide, or `rewind: true` at the end) |
| `last` | `Go to last slide` | none | `aria-label` of the **previous** arrow when it will wrap to the last slide (`type: 'loop'` on the first slide, or `rewind: true` at the start) |
| `slideX` | `Go to slide %s` | `%s` = 1-based slide number | `aria-label` of each pagination button when `perPage` is 1 or a `focus`/`isNavigation` option is set. Also the `aria-label` of each navigation slide (`isNavigation: true`) |
| `pageX` | `Go to page %s` | `%s` = 1-based page number | `aria-label` of each pagination button when `perPage > 1` and neither `focus` nor `isNavigation` is set |
| `play` | `Start autoplay` | none | `aria-label` of the toggle button (`.splide__toggle`) while autoplay is stopped |
| `pause` | `Pause autoplay` | none | `aria-label` of the toggle button while autoplay is running |
| `carousel` | `carousel` | none | `aria-roledescription` of the root element |
| `select` | `Select a slide to show` | none | `aria-label` of the pagination `<ul>` (`role="tablist"`) |
| `slide` | `slide` | none | `aria-roledescription` of each slide. Removed from navigation slides when `slideFocus` is on |
| `slideLabel` | `%s of %s` | 1st `%s` = slide number, 2nd `%s` = total slides (`splide.length`, clones excluded) | `aria-label` of each slide, unless the `<SplideSlide>` has its own `aria-label` |

The `aria-roledescription` attribute gives a non-interactive element a human-readable description for assistive technology.

`label` and `labelledby` (the root's accessible name) are separate options, not part of `i18n`. Translate them too (see `references/accessibility.md`). Set them through `options`, not as an `aria-label` prop: in development, StrictMode mounts the carousel twice and the prop is lost after the second mount, while `options.label` survives (tested).

React Splide v0.7 removed the old `playButtonLabel` and `pauseButtonLabel` props. Their texts are now `i18n.play` and `i18n.pause`.

## How placeholders are filled

From source (`utils/string/format`):

```js
// format( string, replacements ): each replacement fills the FIRST remaining '%s'
string = string.replace( '%s', String( replacement ) );
```

- Placeholders are positional and filled left to right. There is no `%1$s` or `%2$s` syntax, so a translation cannot reorder them. For `slideLabel`, the first `%s` is always the slide number and the second is always the total. Choose wording that keeps that order, for example `'%s / %s'`.
- Extra `%s` stay literal. If you leave one out (for example `slideLabel: 'Slide %s'`), the leftover value is dropped.
- Numbers are inserted as plain JS numbers (`1`, `2`, ...), not localized digits (see [Localized digits](#localized-digits)).
- Labels are computed when components mount. Slide labels are recomputed on `refresh()`, and after `add()` or `remove()`, which refresh too. Pagination labels are recomputed whenever the pagination is rebuilt (`updated`, `refresh`). React Splide calls `refresh()` when the slide children change.
- **(source)** An empty string removes the attribute (Splide's `setAttribute` drops `''`), so `prev: ''` leaves the previous arrow with no accessible name.

## Modifying texts for one carousel

Pass an object to the `i18n` option. Splide merges it into the defaults, so you only list the keys you change:

```tsx
const texts: Options = {
  i18n: {
    prev: 'Previous slide',
    next: 'Next slide',
  },
};

// <Splide options={ texts }> … </Splide>
```

**(source)** The merge is deep and key by key: the built-in defaults, then your `i18n`. Keys you omit keep the default. `Options` is `import type { Options } from '@splidejs/react-splide'` (see `references/options.md` for the setup).

## Changing texts after mount

The `options` prop is reactive, but `i18n` is read when each part of the carousel is built. A change through the prop applies only partly (tested):

| Text | After an `i18n` change in the prop |
|---|---|
| Pagination `aria-label`s (`select`, `slideX`, `pageX`) | Updated at once (the pagination is rebuilt on `updated`) |
| Toggle button (`play`, `pause`) | On its next state change |
| Slide labels (`slideLabel`, `slide`) | Only after `refresh()` (for example when the slide children change) |
| Arrow labels (`prev`, `next`, `first`, `last`) | Never: the arrows keep the texts from mount |
| Root `aria-roledescription` (`carousel`) | Never, not even after `refresh()` |

So to switch language, mount a new carousel: give `<Splide>` a `key` that changes with the language (`key={ locale }`). React unmounts the old instance (`splide.destroy()`) and mounts a new one that reads every text. The new carousel starts at `start` (default `0`); see `references/options.md` (TypeSwitch) for keeping the index.

Changing only `label` or `labelledby` is fine without a remount: they are re-applied on every `updated` (tested).

## Sharing texts between carousels

`Splide.defaults` doesn't work with React Splide: the package bundles its own copy of the core, so setting `Splide.defaults` on `import { Splide } from '@splidejs/splide'` never reaches `<Splide>` (tested). Export the texts from a module and spread them into each carousel's options:

```tsx
// Shared texts: export them from one module and spread them where needed
const frenchTexts: Options = {
  i18n: {
    prev: 'Diapositive précédente',
    next: 'Diapositive suivante',
  },
};

// Spread is shallow: merge `i18n` yourself if a carousel changes one key
const productCarousel: Options = {
  ...frenchTexts,
  perPage: 3,
  i18n   : { ...frenchTexts.i18n, next: 'Produit suivant' },
};
```

## Texts from props

A carousel component that takes translated strings from its parent. Missing keys keep Splide's English defaults:

```tsx
// TranslatedCarousel.tsx
import type { ReactNode } from 'react';
import { Splide, SplideSlide } from '@splidejs/react-splide';
import type { Options } from '@splidejs/react-splide';
import '@splidejs/react-splide/css';

type SplideTexts = NonNullable<Options[ 'i18n' ]>;

interface TranslatedCarouselProps {
  label: string;
  labels?: SplideTexts;
  children: ReactNode;
}

export function TranslatedCarousel( { label, labels, children }: TranslatedCarouselProps ) {
  // Leave `i18n` out when there are no labels: `i18n: undefined` replaces the defaults and throws
  const options: Options = { label, perPage: 2, ...( labels && { i18n: labels } ) };

  return <Splide options={ options }>{ children }</Splide>;
}

const products = [ 'Chemise en lin', 'Écharpe en laine', 'Sac en toile', 'Bonnet' ];

export default function Example() {
  return (
    <>
      <TranslatedCarousel
        label="Produits phares"
        labels={ { prev: 'Produit précédent', next: 'Produit suivant', pageX: 'Aller à la page %s', slideLabel: '%s sur %s' } }
      >
        { products.map( product => <SplideSlide key={ product }>{ product }</SplideSlide> ) }
      </TranslatedCarousel>

      <TranslatedCarousel label="Featured products">
        { products.map( product => <SplideSlide key={ product }>{ product }</SplideSlide> ) }
      </TranslatedCarousel>
    </>
  );
}
```

- Inline `labels={ { … } }` objects are fine. React Splide deep-compares the options, so a re-render with the same strings does nothing.
- **(source, tested)** Splide's merge copies `undefined` like any value. `{ i18n: undefined }` replaces the whole default collection, and the mount throws `Cannot read properties of undefined (reading 'carousel')`. The conditional spread above avoids it.
- Tested: the French carousel gets `Produit suivant`, `Aller à la page 1` and `1 sur 4`; the English one keeps the defaults.

## Texts from an i18n library

Build the `i18n` object from your library's translate function and key the carousel by the language. This component takes any `t( key ) => string`:

```tsx
// CarouselWithT.tsx
import { useState, type ReactNode } from 'react';
import { Splide, SplideSlide } from '@splidejs/react-splide';
import '@splidejs/react-splide/css';

const KEYS = [ 'prev', 'next', 'first', 'last', 'slideX', 'pageX', 'play', 'pause', 'carousel', 'select', 'slide', 'slideLabel' ];

interface CarouselWithTProps {
  lang: string;                   // a new language mounts a new carousel
  t: ( key: string ) => string;   // the translate function of your i18n library
  label: string;
  children: ReactNode;
}

export function CarouselWithT( { lang, t, label, children }: CarouselWithTProps ) {
  const i18n: Record<string, string> = {};
  KEYS.forEach( key => { i18n[ key ] = t( `carousel.${ key }` ); } );

  return (
    <Splide key={ lang } options={ { label, i18n } }>
      { children }
    </Splide>
  );
}

// Demo: a dictionary stands in for the library
const messages: Record<string, Record<string, string>> = {
  en: {
    'carousel.label': 'Photos', 'carousel.prev': 'Previous photo', 'carousel.next': 'Next photo',
    'carousel.first': 'Go to first photo', 'carousel.last': 'Go to last photo', 'carousel.slideX': 'Go to photo %s',
    'carousel.pageX': 'Go to page %s', 'carousel.play': 'Start autoplay', 'carousel.pause': 'Pause autoplay',
    'carousel.carousel': 'carousel', 'carousel.select': 'Select a photo to show', 'carousel.slide': 'photo',
    'carousel.slideLabel': '%s of %s',
  },
  de: {
    'carousel.label': 'Fotos', 'carousel.prev': 'Vorheriges Foto', 'carousel.next': 'Nächstes Foto',
    'carousel.first': 'Zum ersten Foto', 'carousel.last': 'Zum letzten Foto', 'carousel.slideX': 'Zu Foto %s',
    'carousel.pageX': 'Zu Seite %s', 'carousel.play': 'Automatische Wiedergabe starten', 'carousel.pause': 'Automatische Wiedergabe anhalten',
    'carousel.carousel': 'Karussell', 'carousel.select': 'Foto zum Anzeigen auswählen', 'carousel.slide': 'Foto',
    'carousel.slideLabel': '%s von %s',
  },
};

export default function Example() {
  const [ lang, setLang ] = useState( 'en' );
  const t = ( key: string ) => messages[ lang ][ key ];

  return (
    <>
      <button type="button" onClick={ () => setLang( lang === 'en' ? 'de' : 'en' ) }>
        { lang === 'en' ? 'Deutsch' : 'English' }
      </button>
      <CarouselWithT lang={ lang } t={ t } label={ t( 'carousel.label' ) }>
        { [ 1, 2, 3 ].map( n => <SplideSlide key={ n }>{ t( 'carousel.slide' ) } { n }</SplideSlide> ) }
      </CarouselWithT>
    </>
  );
}
```

- Pass `t` from react-i18next's `useTranslation()`, or wrap react-intl's `intl.formatMessage`, into the same slot. These libraries weren't installed in the test harness; the component above was tested with the dictionary `t`.
- Keep `%s` as literal text in your messages. i18next's `{{name}}` and ICU's `{name}` placeholders leave it alone. A sprintf-style post-processor would replace it, so don't run these keys through one.
- Make sure every key exists in every language. Splide puts whatever `t()` returns into the `aria-label`: a missing-key fallback such as the key name ends up read aloud, and an empty string removes the label.
- `t` often gets a new identity on every render. That doesn't matter here: the strings are compared, not the function.
- Tested: switching to German remounts the carousel with `Nächstes Foto` on the next arrow and `Karussell` as the root's `aria-roledescription`.

## Content-based wording

Content-based texts are better when possible. In a list of articles, "Move to next article" fits better than "Move to next slide":

```tsx
const articleTexts: Options = {
  i18n: {
    prev      : 'Previous article',
    next      : 'Next article',
    first     : 'Go to first article',
    last      : 'Go to last article',
    slideX    : 'Go to article %s',
    pageX     : 'Go to page %s',
    select    : 'Select an article to show',
    slide     : 'article',
    slideLabel: 'Article %s of %s',
  },
};
```

## Complete language sets and a language switch (es, fr, ar)

All 12 keys, with `%s` placeholders in the order Splide fills them. Have a native speaker review the strings before shipping. English uses the defaults, so it needs no entry. The `key` on `<Splide>` mounts a new carousel for each language, and `direction` follows the language:

```tsx
// LocalizedCarousel.tsx
import { useState } from 'react';
import { Splide, SplideSlide } from '@splidejs/react-splide';
import type { Options } from '@splidejs/react-splide';
import '@splidejs/react-splide/css';

type Locale = 'en' | 'es' | 'fr' | 'ar';
type SplideTexts = NonNullable<Options[ 'i18n' ]>;

export const SPLIDE_I18N: Record<Exclude<Locale, 'en'>, SplideTexts> = {
  es: {
    prev      : 'Diapositiva anterior',
    next      : 'Diapositiva siguiente',
    first     : 'Ir a la primera diapositiva',
    last      : 'Ir a la última diapositiva',
    slideX    : 'Ir a la diapositiva %s',
    pageX     : 'Ir a la página %s',
    play      : 'Iniciar reproducción automática',
    pause     : 'Pausar reproducción automática',
    carousel  : 'carrusel',
    select    : 'Selecciona una diapositiva para mostrar',
    slide     : 'diapositiva',
    slideLabel: '%s de %s',
  },
  fr: {
    prev      : 'Diapositive précédente',
    next      : 'Diapositive suivante',
    first     : 'Aller à la première diapositive',
    last      : 'Aller à la dernière diapositive',
    slideX    : 'Aller à la diapositive %s',
    pageX     : 'Aller à la page %s',
    play      : 'Démarrer la lecture automatique',
    pause     : 'Mettre en pause la lecture automatique',
    carousel  : 'carrousel',
    select    : 'Sélectionnez une diapositive à afficher',
    slide     : 'diapositive',
    slideLabel: '%s sur %s',
  },
  ar: {
    prev      : 'الشريحة السابقة',
    next      : 'الشريحة التالية',
    first     : 'الانتقال إلى الشريحة الأولى',
    last      : 'الانتقال إلى الشريحة الأخيرة',
    slideX    : 'الانتقال إلى الشريحة %s',
    pageX     : 'الانتقال إلى الصفحة %s',
    play      : 'تشغيل العرض التلقائي',
    pause     : 'إيقاف العرض التلقائي مؤقتًا',
    carousel  : 'عرض دوّار',
    select    : 'اختر شريحة لعرضها',
    slide     : 'شريحة',
    slideLabel: '%s من %s',
  },
};

const RTL_LOCALES: Locale[] = [ 'ar' ];

const titles: Record<Locale, string> = {
  en: 'Featured products',
  es: 'Productos destacados',
  fr: 'Produits phares',
  ar: 'منتجات مميزة',
};

const slides = [ 1, 2, 3, 4 ];

export default function LocalizedCarousel() {
  const [ locale, setLocale ] = useState<Locale>( 'en' );
  const dir = RTL_LOCALES.includes( locale ) ? 'rtl' : 'ltr';

  const options: Options = {
    label    : titles[ locale ],
    perPage  : 2,
    direction: dir, // Splide doesn't read the `dir` attribute
    ...( locale !== 'en' && { i18n: SPLIDE_I18N[ locale ] } ),
  };

  return (
    <div lang={ locale } dir={ dir }>
      <select aria-label="Language" value={ locale } onChange={ e => setLocale( e.target.value as Locale ) }>
        <option value="en">English</option>
        <option value="es">Español</option>
        <option value="fr">Français</option>
        <option value="ar">العربية</option>
      </select>

      {/* i18n and direction are read at mount: a new key mounts the carousel in the new language */}
      <Splide key={ locale } options={ options }>
        { slides.map( n => (
          <SplideSlide key={ n }>{ n }</SplideSlide>
        ) ) }
      </Splide>
    </div>
  );
}
```

Tested: French gives `Diapositive suivante` and `carrousel`; Arabic gives `splide--rtl`, `الشريحة التالية` and `1 من 4`.

If the play/pause toggle has visible text, translate that too, and keep it inside the `play`/`pause` labels (WCAG 2.5.3 Label in Name). For example, visible "Pausar" goes with `pause: 'Pausar reproducción automática'`. The visible text is your JSX (see `references/autoplay.md`), so it re-renders with the language; the `aria-label` comes from `i18n` and needs the remount.

## Arabic and other RTL carousels

**(source)** Splide does not read the `dir` attribute. Set `direction: 'rtl'` yourself, even inside `<html dir="rtl">` or a `dir="rtl"` wrapper. Otherwise the slides move in the LTR direction. With `direction: 'rtl'`:

- The root gets `splide--rtl`, which the core CSS turns into `direction: rtl`. The arrow wrapper gets `splide__arrows--rtl`, and the themes swap the arrow sides and flip the SVGs.
- Pagination keys reverse (Left arrow = next dot), as do the optional `keyboard` shortcuts. Pagination follows `paginationDirection`, which defaults to `direction`.
- Drag and swipe directions reverse.

Derive `direction` from the same locale value that sets `dir`, as `LocalizedCarousel` does above, rather than reading the DOM. Reading `getComputedStyle()` or `document.dir` during render fails in server rendering, and the options are only read once at mount anyway. `direction` is readonly in practice: a change through the prop leaves styles from the old direction on the slides until `refresh()` (tested), so key the carousel by the locale or the direction.

## Localized digits

Splide inserts plain digits. To show localized digits, such as Arabic-Indic numerals, handle two places. Slides keep an `aria-label` you set on `<SplideSlide>`. Pagination buttons can be relabeled in `onPaginationMounted`, which fires every time the pagination is rebuilt:

```tsx
// ArabicDigits.tsx
import { Splide, SplideSlide } from '@splidejs/react-splide';
import type { Options } from '@splidejs/react-splide';
import '@splidejs/react-splide/css';

const nf = new Intl.NumberFormat( 'ar-EG' );

const products = [ 'قميص كتان', 'وشاح صوف', 'حقيبة قماش' ];

const options: Options = {
  label    : 'منتجات مميزة',
  direction: 'rtl',
  i18n     : {
    prev    : 'الشريحة السابقة',
    next    : 'الشريحة التالية',
    carousel: 'عرض دوّار',
    select  : 'اختر شريحة لعرضها',
    slide   : 'شريحة',
  },
};

export default function ArabicDigits() {
  return (
    <div lang="ar" dir="rtl">
      <Splide
        options={ options }
        // Runs every time Splide rebuilds the pagination (mount, options updates, refresh)
        onPaginationMounted={ ( splide, data ) => {
          data.items.forEach( item => {
            item.button.setAttribute( 'aria-label', `الانتقال إلى الشريحة ${ nf.format( item.page + 1 ) }` );
          } );
        } }
      >
        { products.map( ( product, i ) => (
          // A slide's own aria-label wins over i18n.slideLabel
          <SplideSlide key={ product } aria-label={ `${ nf.format( i + 1 ) } من ${ nf.format( products.length ) }` }>
            { product }
          </SplideSlide>
        ) ) }
      </Splide>
    </div>
  );
}
```

- This uses the `slideX` wording. With `perPage > 1`, use the `pageX` wording.
- Tested, also under StrictMode: the second dot reads `الانتقال إلى الشريحة ٢` and the first slide `١ من ٣`. Splide restores a slide's own `aria-label` when it's destroyed, so the StrictMode remount keeps it.
- The handler is bound once at mount and keeps the values from the first render, and it stops firing if a breakpoint destroys and remounts the carousel. With a module-level formatter, as here, the first point doesn't matter; for a formatter that depends on state, key the carousel by the locale. See `references/events.md`.

## Server-rendered pages

- Options, including `i18n`, are read in the browser when `<Splide>` mounts. The server HTML has none of Splide's ARIA attributes yet, and the core CSS keeps the carousel hidden (`.splide { visibility: hidden }`) until it's initialized.
- Translated strings are plain data, so a server component can load the dictionary and pass `labels` (as in `TranslatedCarousel`) or a locale to a client component that renders `<Splide>`. See `references/nextjs.md` for the client-component setup.
- Keep the strings in the props deterministic between server and client, so hydration doesn't warn about the slide text you render yourself.

## What i18n does not cover

- The root's accessible name: the `label` / `labelledby` options.
- Any visible text you render, such as the toggle button's play/pause text, captions or your own arrow text.
- Arrow buttons: their only text is the `aria-label`, and the SVG has none. Arrows you render yourself (`hasTrack={ false }`) get their `aria-label` overwritten from `i18n`, so an `aria-label` prop on them doesn't stick.
- Slides with their own `aria-label` keep it instead of `slideLabel`. Navigation slides (`isNavigation`) always get `slideX`, even if they have their own `aria-label`.
- Digits are not localized (see [Localized digits](#localized-digits)).

## Docs vs source

| Topic | Docs (i18n page) | Source |
|---|---|---|
| `first` | "`aria-label` of a previous arrow" | Used on the **next** arrow when it wraps to the first slide (`Arrows.ts`: `nextIndex > -1 && index > nextIndex ? i18n.first : i18n.next`). The accessibility guide agrees with the source |
| `last` | "`aria-label` of a next arrow" | Used on the **previous** arrow when it wraps to the last slide (`prevIndex > -1 && index < prevIndex ? i18n.last : i18n.prev`) |
| Key order | `select` listed before `slide` | Same keys and texts; only the order differs (`slide` comes before `select` in `I18N`) |
| `select` text | `Select a slide to show` | Same. The accessibility page prints "Select slide to show", which is a typo there |
| Setting texts for all carousels | `Splide.defaults = { i18n }` | Doesn't reach React Splide's bundled core; share an options object |
| `options` prop (React docs) | Reactive | `i18n` changes apply only partly; remount with `key` to switch language |
